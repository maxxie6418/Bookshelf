## 1. 项目定位

个人书单管理工具，单人使用。

- **数据规模**：书籍 ≤ 1000 本。
- **访问特征**：多种网络环境访问（含移动网络、跨地域、弱网），因此"浏览体验"是首要非功能需求。
- **核心价值**：通过书名 / 豆瓣链接或 AI 查询指令录入书籍，自动抓取元数据，以类 Notion 的表格视图与卡片网格视图管理个人书库。

## 2. 技术路线决策

**选定路线 A：Cloudflare 全家桶。**

| 组成 | 选型 |
|------|------|
| 前端 | 轻量 SPA（Tailwind CSS），由 Cloudflare Worker 的 Workers Assets 托管 |
| 后端 API | 单个 Cloudflare Worker（Hono 框架） |
| 数据库 | Cloudflare D1（SQLite） |
| 对象存储 | Cloudflare R2（封面） |
| 边缘 KV | Cloudflare KV（登录失败封锁 / 轻量缓存；**会话用签名 Cookie，不存 KV**） |
| 数据访问层 | Drizzle ORM（drizzle-orm/d1），与 Redesk 一致便于迁移 schema |

**选型理由**：

1. 静态资源、计算、数据同处 Cloudflare 边缘、无 Serverless 冷启动、缓存最可控 → 在"小数据 + 多网络访问"前提下浏览体验最佳。
2. 用户确认"开发全程 AI 执行、不需要可视化 Dashboard"，抵消了 Supabase（路线 C）在图形化管理上的 DX 优势。
3. D1 / R2 / KV 免费额度可覆盖个人量（<1000 本）。

## 4. 数据模型设计（D1 / SQLite）

| 表 | 关键字段 | 说明 |
|----|---------|------|
| users | id, username, display_name, password_hash, is_admin, must_change_password, created_at, updated_at | 单用户 |
| books | id, title, subtitle, author, translator, publisher, publish_year, page_count, isbn, description, cover_url, douban_url, rating, status('unread'\|'reading'\|'finished'\|'shelved'), favorite, category_id→categories, sort_order, source('douban'\|'neodb'\|'openlibrary'\|'googlebooks'\|'manual'), started_at, finished_at, deleted_at, created_at, updated_at | 核心实体；软删用 deleted_at |
| categories | id, name, color | 自定义分类 |
| tags | id, name | 标签 |
| book_tags | book_id, tag_id（联合主键） | 多对多 |
| settings | key, value, updated_at | 存 AI_BASE_URL 等；密钥类走 secret 不入库 |

- **索引**：books(status)、books(category_id)、books(updated_at)、books(isbn)、books(deleted_at)。
- **login_guard**：用 KV 存储（见 §5），不建表。
- **ai_query_log**（可选，M4）：id, query_text, filter_json, row_count, ip, created_at, ok —— 轻量记录，不做重型审计。
- **删除策略（软删除 + 回收站）**：正常查询 `WHERE deleted_at IS NULL`；回收站 `WHERE deleted_at IS NOT NULL`；二次确认后物理删除（`book_tags` 因 `ON DELETE CASCADE` 级联清除）。详见 §4.1。
- **设计原则**：单租户，所有数据归属唯一用户；外部 API / 密钥不进客户端；查询全部参数化，禁止字符串拼接 SQL。

### 4.1 回收站设计（软删除 + 二次确认物理删）

- **删除分两步**：`DELETE /api/books/:id` 仅置 `deleted_at`（软删，进入回收站）；`DELETE /api/books/trash/:id` 才是物理删除（不可逆）。
- **恢复**：`POST /api/books/:id/restore` 清 `deleted_at`，书本与标签关联一并回到正常列表。
- **回收站列表**：`GET /api/books/trash`，按 `deleted_at DESC`。
- **前端**：侧栏"回收站"入口（含数量角标）；回收站内对"彻底删除 / 清空"做**二次确认弹窗**。
- **级联**：物理删触发 `book_tags` 的 `ON DELETE CASCADE`；软删期间关联保留以便恢复。

## 5. 权限与鉴权设计

- **单租户 + 单用户**。所有写接口前置登录校验；未登录仅可访问登录页。
- **登录**：口令 bcrypt / argon2 哈希存储；成功后签发 HttpOnly + Secure + SameSite 签名会话 Cookie（无状态，免 session 表）。
- **失败封锁（brute-force，KV 持久化版）**：按 `login:${ip}` 计数，窗口内（默认 15 分钟）失败达阈值（默认 5 次）→ 封锁（默认 30 分钟），返回 429 与剩余分钟数。采用 Redesk `brute-force.ts` 思路，但存储从内存 Map 改为 KV，使封锁在 Worker 多实例间生效。
- **路由守卫**：未登录请求受保护资源 → 401 / 重定向登录页。

## 6. 豆瓣信息获取设计

- **服务端抓取**：`fetch` 书页 HTML → **手写正则解析**（不引 cheerio，Worker 友好、省 CPU / 体积）。
- **反爬**：随机桌面 UA + Referer 伪装；按域限速；10s 超时（AbortController）；3 次指数退避重试 + 抖动；遇 429 读 `retry-after` 后重试。
- **兜底链（关键稳定性来源）**：豆瓣 → NeoDB(`neodb.social`) → Open Library（按 ISBN）→ Google Books（按 ISBN / 书名）→ 手动粘贴。后三者为干净 JSON API，不怕数据中心 IP。
- **解析字段**：标题 / 副标题（书名冒号后的一句话简介） / 作者 / 译者 / 出版社 / 出版年 / ISBN / 页数 / 简介 / 封面 / 评分；记录 `source` 来源。
- **封面**：`cover_url` 存远程地址，经 Cloudflare Image Resizing 按需代理下发（防 doubanio 防盗链、按视图尺寸缩放、边缘缓存）；首版**不主动写 R2**，R2 桶保留备用。
- **缓存**：URL / ISBN → 元数据缓存（KV / DB），避免重复抓取。
- **失败降级**：抛"获取链接失败，请改用粘贴文本导入"。
- **风险探针（M3）**：先用 Worker 实测能否抓到豆瓣（数据中心 IP 可能被封）；抓不到则主用 NeoDB / Open Library / Google Books。

## 7. AI 查询设计（baseurl + api key）

- **配置**：`AI_API_KEY` 必须走 `wrangler secret`（密钥不入库、无 UI 收集）；`AI_BASE_URL` 可放 `settings` 表或同样走 secret。应用服务端持有，不下发客户端。弃用 Redesk 复杂的 agent-token（令牌 / scope / 审计 / 白名单）体系。
- **链路**：用户（自然语言）→ `/api/query`（需登录）→ 应用用 baseurl + key 调 LLM（OpenAI 兼容）→ LLM 返回**结构化过滤条件 JSON**（如 `{status, tags[], authorContains, titleContains}`）→ 应用对本地 D1 跑**参数化只读查询** → 返回匹配书目。
- **只读保证**：LLM 只产出过滤条件，真正的查询由应用用参数化语句执行 → 结构上不可能误删 / 清库；无需 token / scope / 审计白名单。
- **可选**：`ai_query_log` 轻量记录（查询 / 过滤 / 结果数），不做重型审计。

## 8. 数据导入设计

与 §3.2 的"数据导出"成对，保证书库可备份 / 可迁移 / 可还原。

- **格式**：与导出一致的 **JSON（主）/ CSV**。导出即导入的反操作，字段一一对应。
- **端点**：`/api/import`（登录保护）。接收 JSON / CSV 文本或文件。
- **匹配与 upsert**：
  - 优先按 `isbn` 匹配已存在书目；无 ISBN 或匹配失败时按 `title + author` 模糊匹配。
  - 命中 → 更新（仅覆盖本次提供的字段）；未命中 → 新建。
  - 分类 / 标签：按 `name` 复用，不存在则自动新建（带默认色）。
- **返回统计**：`{ imported, updated, skipped, errors[] }`，`errors` 含行号与原因，便于用户修正。
- **幂等**：相同 ISBN 重复导入为"更新"而非"新建"；单次全量即可（<1000 本，无需流式）。
- **安全**：登录门禁；不导入 / 覆盖账户与密钥；字段校验失败进入 `errors`，不中断整体。
- **Redesk 迁移（可选 P2）**：Redesk 的导出 / API 字段结构与本项目不同，提供一次性映射脚本（`scripts/migrate-from-redesk.ts`）将 Redesk JSON 对齐到本项目 schema；不阻塞首版。

## 9. 部署与一键部署

- **单 Worker**：Workers Assets 托管 `dist` SPA + API。
- **wrangler.toml** 声明：D1 / R2 / KV / Assets / vars。`AI_API_KEY`、`SESSION_SECRET`、`INITIAL_ADMIN_PASSWORD` 为 secret。
- **一键部署脚本** `scripts/setup`（`npm run deploy`）：`wrangler login`（或 `CF_API_TOKEN`）→ `d1 create` → `r2 create` → `kv create` → 跑迁移 → `secret put` → `wrangler deploy`。
- **前提**：免费 Cloudflare 账号 + `npx wrangler`；AI baseurl / key 由用户提供。
- **本地**：`wrangler dev` 起全栈。

### 10.3 设计约束（呼应 AGENTS.md）

- 外部 API / 密钥只在 `src/lib` 与 Worker 服务端使用，前端不持有。
- 路由层（api）只做校验与编排，复杂逻辑下沉到 `src/lib`。
- 数据访问集中在 `lib/db.ts`，禁止在组件 / 路由拼接 SQL。
- 新增代码按职责落入上述目录，不随意新建顶层目录。

## 12. 关键风险与缓解

| 风险 | 缓解 |
|------|------|
| 豆瓣封数据中心 IP | 兜底链（NeoDB / Open Library / Google Books）+ M3 探针 |
