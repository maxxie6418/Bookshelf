## 修改摘要

背景：M2 视觉回归通过 Trae 内置浏览器逐项验证登录/改密/网格/表格/主题/筛选/回收站/恢复/设置/退出时，发现两个交互 bug 与一个 UI 重复入口：

### Bug 1：回收站列表显示错误数据（trash 参数编码不一致）

现象：回收站视图显示「共 2 本」两个条目，但后端回收站实际只有 1 本；在回收站点「恢复」后 UI 无变化。

根因：前端 `api.ts` 的 `qs()` 用 `String(v)` 序列化布尔参数，`trash: true` 编码为 `trash=true`；后端 `books.ts` 只认 `q.trash === '1'`，导致 `trash=true` 被忽略 → 视为非回收站查询，返回全部书籍（2 本）。回收站「恢复」其实作用在当前 `state.books`（全部书籍）上，对正常书籍发恢复请求，无害但 UI 不变。

修复：`src/web/api.ts` 的 `qs()` 中将布尔值统一编码为 `1`/`0`，与后端 `trash === '1'` 契约对齐。

### Bug 2：回收站视图下点击筛选无法切回主视图

现象：进入回收站后点击侧栏「全部书籍/未读/在读/读完」等筛选项，主区仍渲染回收站。

根因：`renderSidebar` 的 `clickFilter` 仅更新 `filters` 并 `refresh()`，未把 `viewMode` 切回 `'main'`；而 `mountAppShell` 的 `render()` 依据 `viewMode === 'trash'` 决定渲染 `renderTrash`。

修复：`src/web/components/app-shell.ts` 的 `clickFilter` 中在设置 filters 的同时将 `viewMode` 置为 `'main'`（状态/分类/标签筛选恒针对主视图藏书）。

### Bug 3（此前遗留，本次随批提交）：书籍表单抽屉关闭后残留遮罩

原因与修复详见之前会话；`book-form.ts` 改为保存 overlay 引用并 `overlay?.remove()`，避免 `document.body.lastElementChild` 误删 toast-root 导致遮罩残留遮挡卡片。

### 需求调整：移除重复「添加书籍」+ 顶栏操作按钮迁移

- 移除顶栏重复的「添加书籍」按钮（桌面端顶栏与列表工具栏重复），保留列表工具栏按钮 + 移动端 FAB。
- 「切换主题/设置/退出」三个按钮从顶栏右下移至左侧栏最底部，竖排图标按钮（用户确认的样式），顶栏右侧留空占位保持布局对称。
- 侧栏容器改为 flex-col，底部操作区 `mt-auto` 贴底。

涉及文件：

- `src/web/api.ts`：qs() 布尔编码修复
- `src/web/components/app-shell.ts`：clickFilter 视图切换修复 + 顶栏/侧栏重构
- `src/web/components/book-form.ts`：overlay 引用关闭修复
