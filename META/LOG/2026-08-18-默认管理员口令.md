## 修改摘要

背景：用户一键部署时未填写 `INITIAL_ADMIN_PASSWORD`，原逻辑因缺少该 secret 跳过 seed 初始管理员，导致无法登录。

修改：`src/lib/bootstrap.ts` 的 `ensureAdmin` 在 users 表为空时，口令取 `env.INITIAL_ADMIN_PASSWORD || 'admin123'`；`must_change_password=1`（首登强制改口令）保持不变。

涉及文件：

- `src/lib/bootstrap.ts`：默认口令分支
- `README.md`：一键部署说明与 secret 设置注释同步（admin/admin123 默认值提示）
- `.dev.vars.example`：`INITIAL_ADMIN_PASSWORD` 注释同步

## 验证情况

- `npm run typecheck`：通过
- 本地 `wrangler dev` 实测（本地 D1 users 表为空，且 `.dev.vars` 未设置 INITIAL_ADMIN_PASSWORD，等价首次部署）：
  - 触发 `ensureAdmin` 后自动 seed admin 用户
  - `POST /api/auth/login` 口令 `admin123` → 200，返回 `{username:"admin", is_admin:true, must_change_password:true}`
  - 错误口令 → 401（原有拒绝逻辑正常）

## 未验证内容与剩余风险

- 未在远程环境实测；远程首次部署后首次访问将触发相同的 seed 逻辑（users 表为空时）
- 默认口令 admin123 为公开弱口令，存在「先到先得」风险：谁先访问站点即可用 admin/admin123 登录并改密。缓解措施：`must_change_password=1` 强制首登改密；建议部署后立即登录并修改口令，且修改后请勿回填弱的默认口令

## 后续操作

- 用户重新走一键部署（或 `npm run deploy`）使新代码生效
- 部署完成打开站点 → admin / admin123 登录 → 按引导强制修改口令
