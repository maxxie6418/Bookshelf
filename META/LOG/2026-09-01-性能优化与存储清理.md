## 需求与现象

1. 项目部署在 Cloudflare Worker 上，性能有优化空间：首次加载（Google Fonts 第三方阻塞 + 首屏拉全量列表）、录入/抓取更新（每次抓豆瓣重复下载封面与解析）、编辑（一次操作多个串行请求）。
2. 存储治理：抓取产生的豆瓣元数据缓存与 R2 封面在书籍删除后未被清理，会残留为孤儿资源。

## 已确认的设计决策

- 字体：Noto Serif SC / JetBrains Mono 从第三方 CDN 改为 `@fontsource` 自托管（构建期打包 woff2，同域加载 + `font-display: swap` 已由 index.html 原有 CSS 兜底）。
- 首屏：新增 `GET /api/books/stats` 聚合统计，前端 `refresh()` 改为「列表 + stats」并发 2 请求，不再拉全量书籍做侧栏计数。
- 冷启动：`ensureAdmin` 引导完成后写 `bootstrap:ready` KV 标志，后续请求 1 次 KV 读即跳过全部 D1 检查。
- 抓取：豆瓣解析结果回写 KV（`meta:douban:subject:{id}` 与 `meta:douban:isbn:{isbn}`，TTL 24h）；`force` 参数可绕过缓存强制刷新（列表「抓取刷新」按钮用 force=true）；封面已存在时 `bucket.head()` 复用不重复下载。
- 存储治理：彻底删除 / 清空回收站时按书收集候选键（douban_url→subject 键、isbn 键、cover_url→封面键），batch 查询引用数，仍被任何书（含回收站）引用的资源不删；设置页新增「存储检查与清理」卡片，可手动列出并清理孤儿。
