## 修改摘要

背景：Cloudflare 账号中 bookshelf 的 KV namespace 被删除，导致：

- 线上部署被拒：`Invalid deployment ... binding "KV" references KV Namespace "bb9833ab..." that no longer exists [code: 10210]`
- 生产配置 `wrangler.prod.toml` 中 KV 绑定写死旧 ID（REDACTED_OLD_KV_NAMESPACE_ID，已被删除）
- 进一步排查发现 `wrangler.prod.toml` 中 D1 database_id（0ada7726）与账号实际 ID 不符 [code: 10181]
- 本地 node_modules 的 wrangler 为 3.114.17，与 package.json 声明 `^4.123.0` 不匹配

修改内容：

1. 新建 KV namespace 并绑定：
   - 实际创建 title 为 `worker-bookshelf-kv`（3.x 无配置前缀），ID：`REPLACE_WITH_KV_NAMESPACE_ID`
   - 账号当前 KV 列表确认无 `bookshelf-kv`，重建后绑定新 ID
2. `wrangler.prod.toml`：
   - KV `id`：`REDACTED_OLD_KV_NAMESPACE_ID...` → `REPLACE_WITH_KV_NAMESPACE_ID`
   - D1 `database_id`：`0ada7726...` → `REPLACE_WITH_D1_DATABASE_ID`（账号实际 ID，`wrangler d1 list` 确认）
3. `.wrangler-ids.env`：同步 D1_DATABASE_ID / KV_NAMESPACE_ID
4. 依赖修复：`npm install` 将本地 wrangler 恢复为 4.123.0

涉及文件：

- `wrangler.prod.toml`：KV id、D1 database_id
- `.wrangler-ids.env`：两个 ID 同步

## 未验证内容与剩余风险

- **CI（GitHub Push → Cloudflare Workers 部署）仍使用 `wrangler.jsonc`（KV/D1 均无 ID）**：auto-provisioning 行为依赖平台环境，下次推送可能新建 KV namespace 或报绑定错误；如再失败需在 Cloudflare 控制台重绑 KV 或在配置中固化有效 ID
- 重建后的 KV 为空 namespace：登录封锁计数、Agent Key、限频计数均被清空；**AI Agent Bearer Key 需在设置面板重新创建**（旧 Key 已失效）
- `scripts/prepare-kv.mjs` 调用的 `wrangler kv namespace list --json` 在 wrangler 4.x 已不支持 `--json`，会打印"无法查询 KV 列表"警告并跳过复用（不影响带 ID 的 prod 配置部署；如需按名复用，建议后续改用 `KV_LIST_JSON` 环境变量或适配新参数）
- `wrangler.prod.toml` 与 `.wrangler-ids.env` 为本地未跟踪文件，含账号私有资源 ID，按项目原则不提交仓库
