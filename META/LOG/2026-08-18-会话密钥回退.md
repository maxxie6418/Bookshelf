## 修改摘要

背景：用户远程登录 admin123 返回 500。通过 observability 日志定位根因：
`DataError: Imported HMAC key length (0) must be a non-zero value ...`
即 `SESSION_SECRET` 在云端为空（长度 0），`crypto.subtle.importKey('HMAC')` 无法用空串作密钥，登录签发会话 Cookie 时崩溃。

修改：`src/lib/session.ts` 新增 `sessionSecret(env)`：

- `SESSION_SECRET` 非空且长度 ≥16 → 直接使用（生产推荐路径）
- 否则从稳定输入（`APP_NAME` + `INITIAL_ADMIN_PASSWORD` 或固定盐）用 FNV-1a 派生固定长度的回退密钥，确保：
  - 登录不崩、会话可签发/验签
  - 密钥稳定：同一 Worker 配置下重启后不变，已登录会话不失效
- `signSession` / `verifySession` / `hmac` 统一改用 `sessionSecret(env)`

## 验证情况

- `npm run typecheck`：通过
- 本地精确复现（临时将 `.dev.vars` 的 SESSION_SECRET 置空后启动 wrangler dev）：
  - `GET /api/health` → 200 `{"ok":true}`
  - `POST /api/auth/login` 口令 admin123 → 200，返回 admin 数据，且正确签发 `bs_session` Cookie（HMAC 签名成功，未再抛 DataError）
  - 测试后已恢复 `.dev.vars` 原值

## 未验证内容与剩余风险

- 回退密钥基于 `APP_NAME`/`INITIAL_ADMIN_PASSWORD` 派生，非真正随机，安全性低于显式 `SESSION_SECRET`；仅作为兜底，生产应设置真实 secret
- 未在远程实测；本地逻辑与远程一致，预期修复

## 后续操作与安全建议

- 根因仍是 `SESSION_SECRET` 未设置。用户重新部署后应执行 `npx wrangler secret put SESSION_SECRET`（≥16 字节随机串）彻底根治
- 若一键部署向导要求填 `SESSION_SECRET` 而实际未生效，建议以 `wrangler secret put` 方式显式设置一次
- 设置真实 secret 后，使用回退密钥签发的既有会话将失效（属预期，重新登录即可）
