## 现象

用户浏览器中书架"书籍全部消失"：侧栏总藏书显示 0、列表空态，右下角 toast「请求失败(500)」。

## 排查过程

1. 确认 D1 数据完好：books=213、users=1、categories/tags/book_tags 均有数据，表结构完整（PRAGMA table_info 全列存在）。
2. 分类计数正常（listCategories LEFT JOIN books）→ 与"总藏书 0"矛盾，指向 /api/books 接口异常。
3. 构造只读探测会话（线上未配置 SESSION_SECRET，使用 fallback 派生密钥签名可复现登录态），批量扫描接口参数组合：
   - `/api/books?limit=5 / limit=60 / status=* / favorite=1 / trash=1 / q / category_id / sort=*` 均 200
   - **`/api/books?limit=1000` → 500（复现）**
4. 开启 observability 后 wrangler tail 捕获异常栈：
   - `D1_ERROR: too many SQL variables at offset 330: SQLITE_ERROR`
5. 根因：`src/lib/books.ts` 的 `tagsForBooks` 将本次列表返回的全部 bookId 一次性拼入 `IN (?,?,...)` 并 bind。D1 单查询绑定变量数有限（约 100），书架 213 本全部展开后超限。前端 `refresh()` 的侧栏统计请求 `limit=1000`（ALL_LIMIT）返回 213 行 → 触发；`Promise.all` 整体失败 → 列表空、总藏书 0、toast 500。

## 修复方案

`tagsForBooks` 改为分批查询：每批最多 90 个 book_id 拼一个 IN 子句分别查询后合并结果，避免绑定变量超限。同时覆盖 `listAllBooks`（导出/导入去重，pageSize=500）潜在的同问题。

涉及文件：

- `src/lib/books.ts`：`tagsForBooks` 分批查询
