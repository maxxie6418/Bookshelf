## 问题与根因

- 用户报告：① 添加书籍时已抓取到简介，保存后详情里简介为空，需重新编辑再抓取才能存上；② 添加时填写的录入理由保存后丢失。
- 根因：v1.2.0「列表瘦身」优化（commit 9509b76）使 `GET /api/books` 列表项不再返回 `description / notes / reason` 三个详情大字段，但详情抽屉 `renderDrawer(book)` 仍直接使用列表项渲染，导致这三个字段被误显示为「暂无」。
- 数据实际未丢失：创建接口 `POST /api/books` 与数据库 INSERT 均正确写入这两个字段（本地端到端验证确认详情接口可返回），纯前端展示层回归。
- 连带隐患：抽屉内点「编辑」时表单以列表数据初始化，简介/理由/笔记输入框为空，不抓取直接保存会用空值 PATCH 覆盖已存内容；列表行「抓取刷新」用列表数据判断「非空不覆盖」，`description` 恒判空导致抓取结果覆盖已有简介。

## 修改摘要

- 修改 `src/web/components/detail-drawer.ts`：`renderDrawer` 改为 async，打开抽屉前先 `api.getBook(id)` 补拉全量详情再渲染；补拉失败时 toast 提示并降级用列表数据渲染（保持可用）。
- 修改 `src/web/components/book-list.ts`：
  - 表格行 / 网格卡片打开抽屉的调用改为 `void renderDrawer(b)` 适配异步。
  - `refreshMeta`（行内「抓取刷新」按钮）在计算 `metaToPatch` 前先 `api.getBook(b.id)` 取全量数据，恢复「已有属性不覆盖」策略对 `description` 字段的效力。
- 未修改数据库 schema、后端 API、认证逻辑；创建/更新接口行为不变。

## 验证情况

- `npm run typecheck`：通过。
- 本地 `wrangler dev` + curl 端到端验证：
  - `POST /api/books` 携带 `description` + `reason` 创建成功，响应含两字段；
  - `GET /api/books`（列表）确认不返回 `description / notes / reason`（复现根因）；
  - `GET /api/books/:id`（详情）确认返回两字段（抽屉补拉后可正确显示）；
  - 测试书籍已通过 API 删除清理（软删 + 彻底删除，库中确认无残留）。
- 未做浏览器 UI 手工验证；抽屉打开会因补增加一次详情请求而略有延迟（单行主键查询，通常为毫秒级）。
- 剩余风险：若补拉详情失败（网络异常），抽屉以列表数据降级展示，此时在抽屉内不抓取直接保存仍可能用空值覆盖简介/理由/笔记（与修复前行为一致，概率低）。
