## 修改摘要

背景：用户一键部署后登录报 500。根因：「Deploy to Cloudflare」云端构建只执行「构建 + 部署」，不会执行 `wrangler d1 migrations apply`；远程 D1 为空库，登录接口的 `ensureAdmin` 查询 users 表时因缺表抛 `no such table: users`。

方案：将幂等建表逻辑内嵌进 Worker 引导流程，任何部署方式首次请求即自动建表。

涉及文件：

- 新增 `src/lib/schema.ts`：从 `migrations/0000_init.sql` 内联导出 `SCHEMA_STATEMENTS`（语句数组，全部 `IF NOT EXISTS` 幂等）
- `src/lib/bootstrap.ts`：新增 `ensureSchema()`：检测 users 表，缺失时用 `env.DB.batch(SCHEMA_STATEMENTS.map(s => env.DB.prepare(s)))` 建表，再执行原有 seed admin 逻辑

实现约束（踩坑记录）：
- D1 `exec()` 在 miniflare 本地模拟下不支持多行多语句字符串（按行拆分报 `incomplete input`），也不支持 `--` 注释行 → 改用 `batch()` + 单语句数组，且不保留 `--` 注释
- schema 与迁移文件的同步：以 `migrations/` 为权威源；后续增量迁移仍走 migrations 目录 + 部署流程 apply，不得在 `schema.ts` 追加新表
