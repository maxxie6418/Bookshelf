## 修改摘要

背景：一键部署在 KV 自动创建阶段报 `a namespace with this account ID and title already exists [code: 10014]`。经查为 wrangler 官方已知 bug：对 KV 的 auto-provisioning 不做同名查重（D1/R2 按名复用，KV 不按名复用），且云端构建环境非幂等（每次部署都会尝试创建同名 namespace）。修复 PR（#14286）尚未发布。

需求：改为「遇到同名的直接使用」。

方案：新增 `scripts/prepare-kv.mjs` 挂在 `npm run build` 之前执行：

- 查询 `wrangler kv namespace list --json`（支持 `KV_LIST_JSON` 环境变量注入模拟列表，便于测试/文档化）
- 发现 title 为 `bookshelf-kv` 的同名 KV（不区分大小写）或匹配 `BOOKSHELF_KV_ID` 时，将其 ID 写入 `wrangler.jsonc` 的 KV binding → `wrangler deploy` 直接复用，不再触发创建（不撞名）
- 未发现同名时：若配置中残留旧 ID 则自动移除（自愈，避免部署用到失效 ID），否则保持无 ID 交给 wrangler 首次自动创建，后续部署再查即可复用
- 未登录/查询失败：打印提示并跳过，不阻塞本地构建（本地未登录时 wrangler 自动创建同样不可用，属预期）

涉及文件：

- 新增 `scripts/prepare-kv.mjs`
- `package.json`：`build` 由 `vite build` 改为 `node scripts/prepare-kv.mjs && vite build`
- `README.md`：一键部署/自动资源创建说明补充 KV 同名复用说明与注意事项

兼容性说明：官方修复 #14286 发布后本逻辑依然无害（有 ID 时 wrangler 直接复用，无 ID 时走官方幂等创建）。

## 验证情况

- 本地四场景模拟（`KV_LIST_JSON` 注入假数据）：
  - 未登录/查询失败 → 打印跳过提示，wrangler.jsonc 不变
  - 存在同名 KV（title=bookshelf-kv）→ 正确注入其 ID 到 KV binding
  - 已注入后再次运行 → 幂等跳过
  - 同名消失（空列表）→ 自动移除失效 ID，配置恢复干净
- `npm run typecheck`：通过
- `npm run build`：prepare-kv 未登录跳过 → vite build 成功，整条命令链路正常
- 测试后 `wrangler.jsonc` 已恢复为无 ID 原始状态（git diff 仅 package.json 与 README）
