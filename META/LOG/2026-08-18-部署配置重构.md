## 修改摘要

背景：README 一键部署按钮 / Workers Builds 远程构建时，`wrangler.toml` 中的占位资源 ID（D1 `01234567-89ab-cdef-0123-456789abcdef`、KV `0123456789abcdef0123456789abcdef`）被原样用于部署，但云账号中不存在这些资源，报 `KV namespace not found [code: 10041]`。

方案：改为 Wrangler 4.45+ 官方自动资源创建（auto-provisioning），配置中不携带任何账号私有 ID。参考官方 changelog（2025-10-24）与 workers-sdk issue #13632（TOML 不支持 ID 回写、d1 子命令依赖 database_id）。

涉及文件：

- `wrangler.toml` → 删除，转写为 `wrangler.jsonc`：
  - 删除 D1 `database_id`、KV `id` 占位符
  - 保留 D1 `database_name=bookshelf`、R2 `bucket_name=bookshelf-covers`（按名字复用已存在资源）
  - 保留 assets/vars/兼容性日期等原有配置
- `package.json`：`wrangler` `^3.90.0` → `^4.123.0`；`@cloudflare/workers-types` `^4.20241127.0` → `^5.20260811.1`（wrangler 4.123 peer 依赖要求）
- `scripts/deploy.mjs`：重写为「构建 → wrangler deploy（自动创建/复用资源）→ d1 migrations apply --remote → 恢复配置（保持仓库不含真实 ID）」
- `scripts/setup.mjs`：同步新流程，保留初始管理员口令生成提示
- `scripts/seed-local.mjs`：不变（本地 seed 与资源 ID 无关）
- `.wrangler-ids.env`：删除（不再需要）；`.gitignore` 移除 `.wrangler-ids.env`、`wrangler.prod.toml` 条目
- `README.md`：更新部署章节（自动资源创建说明、新命令说明）
- `src/env.ts`：注释同步为 wrangler.jsonc

## 部署行为变化

- 本地 `npm run deploy` / `npm run setup`：自动创建或复用 D1 `bookshelf`（数据库/库中已存在则复用，保留数据）、R2 `bookshelf-covers`（复用已有桶）；KV 按绑定名自动创建
- 一键按钮 / Workers Builds：配置不含 ID 时官方自动创建资源，他人 fork 后也能一键部署到自己的账号
- 本地 `wrangler dev`：本地模拟资源，行为不变

## 未验证内容与剩余风险

- 未在真实 Cloudflare 账号执行 `npm run deploy`（需要用户本地 `wrangler login` 凭据）；远程资源自动创建/复用的最终行为需用户实际运行确认
- 旧手动创建的 KV 命名空间（`bookshelf-kv`，id `ee1638be...`）名称与自动创建规则不一致时不会被复用，可能产生冗余 KV namespace，可在 Cloudflare 控制台手动删除
- wrangler 4.x 新主版本仅影响 dev/deploy 流程，不影响 runtime 代码；已通过本地 dev 全链路验证
- 部署后恢复配置文件会丢弃 auto-provision 回写的 ID，因此每次部署都可能重新查询/复用资源，属预期行为
