## 背景与需求

用户在表格（列表）视图中希望：

1. 点击「编辑」按钮后，**不弹窗、不跳转**，直接在当前行的位置编辑书籍属性，减少打开弹窗/抽屉的打断。
2. 在列表上加「抓取刷新」按钮，快速用豆瓣元数据刷新书籍信息。
3. 目标：让表格视图能兼顾「批量管理」——因交互与复杂度考虑，经确认采用**逐本快速编辑**形态（不做勾选多选批量操作）。

## 已确认的交互决策

| 决策点 | 结论 |
|-------|------|
| 批量形态 | 单行内联编辑（不做多选批量） |
| 行内可编辑字段 | 高频字段：状态、分类、评分、收藏、标签 |
| 抓取刷新行为 | 有豆瓣链接或 ISBN 的书籍显示「刷新」按钮；一键抓取并直接保存入库（成功才写，失败不动原数据） |
| 实现形态 | 方案 A：整行替换为编辑行（控件预填原值，保存/取消还原） |

## 功能设计

### 1. 行内编辑行（方案 A）

- 在表格视图行操作区点击「编辑」铅笔图标 → 该行整体替换为**编辑行**（`<tr>`），原展示单元格切换为一组紧凑控件。
- 编辑行内包含（自左至右，尽量对齐原列宽）：
  - 书名（只读，灰色），作为编辑时的上下文参照，不参与保存；
  - 状态：下拉（未读/在读/读完/搁置）；
  - 分类：下拉（无分类 + 全部分类）；
  - 评分：数字输入（0–10，步进 0.1）；
  - 收藏：勾选框；
  - 标签：文本输入（逗号分隔）；
  - 操作：保存 / 取消。
- 控件初始值来自当前书籍数据。
- **保存**：收集字段变更 → `PATCH /api/books/:id`（提交行内全部字段值，等价于所见即所得；书名不参与）→ 成功 toast「已保存」→ 刷新列表与侧栏 → 退出编辑态。
- **取消**：直接还原展示行，不调用接口。
- 校验：评分为空或非法时提示「评分需为 0–10 的数字」；暂无其它必填项（书名不在行内编辑范围）。
- 进入编辑态后，该行的行点击（打开详情抽屉）与收藏按钮应停止响应（避免误触）。

### 2. 抓取刷新按钮

- **显示条件**：仅当书籍 `douban_url` 或 `isbn` 非空时，在行操作区显示「刷新」图标按钮（置于收藏按钮之前）。
- **点击行为**：
  1. 按钮置为加载态（禁用，防止重复点击）；
  2. 调 `api.fetchMetadata`，入参按 `isbn` 优先、`douban_url` 兜底；
  3. 成功 → 将元数据映射为更新字段，调 `PATCH /api/books/:id` 直接保存（封面走接口返回的站内代理地址）；
  4. toast 结果（成功「已刷新《书名》」/ 失败显示接口错误信息）；
  5. 无论成功失败，结束后恢复按钮态。
- **失败保护**：抓取或保存任一步失败，只 toast，不修改原数据。
- **字段映射**：title、author、translator、publisher、publish_year、page_count、original_title、isbn、description、rating（=douban_rating）。
  - `cover_url`：**仅当元数据非空时**更新（防抓取失败把封面清空）；
  - `douban_url`：**不参与更新**（保留原值，避免 ISBN 抓取路径返回 null 时把已有豆瓣链接清空）；
  - 该映射与现有 `book-edit-form` 的 `fill()` 取值口径一致，逻辑内聚于 inline-edit 组件。

### 3. 入口共存

- 行点击 → 详情抽屉（不变）。
- 操作区「编辑」铅笔 → 行内编辑（新行为，替代原先的打开弹窗 `openBookForm`）。
- 完整字段编辑（书名/作者/简介/记录/理由等）仍可从**详情抽屉**进入（现有 `enterEdit` 不变）。
- 收藏快捷按钮保留（编辑态中禁用）。
- 回收站视图、网格视图不改变。

## 组件与数据流

- 新增 `src/web/components/book-inline-edit.ts`
  - 导出 `createInlineEditRow(book, { onCancel, onSaved }): HTMLTableRowElement` 与 `metaToPatch(meta): Partial<Book>`；
  - 内部构建控件、收集变更、校验（评分 0–10）、调用保存；
  - `onCancel` 由调用方还原普通行；`onSaved` 由调用方换回普通行并刷新列表与侧栏。
- 修改 `src/web/components/book-list.ts`
  - 行构建抽为 `renderBookRow(b)`，供初始渲染与行内编辑后恢复复用；
  - 行操作区「编辑」点击后，用 `createInlineEditRow` 生成的编辑行**就地替换**当前行（纯 DOM 操作，滚动不跳动）；保存成功换回普通行并静默刷新，取消直接还原；
  - 操作区新增「抓取刷新」按钮（仅 `douban_url` 或 `isbn` 非空时显示），点击走「抓取刷新」流程，按钮加载态为局部 DOM 切换。
- 修改 `src/web/ui.ts`
  - 新增 `iconRefresh`（旋转箭头）与 `iconCheck`（对勾），供刷新按钮与保存按钮使用。
- 不修改后端接口：`PATCH /books/:id` 与 `POST /books/metadata/fetch` 已满足需求。

数据流（编辑保存）：

```
点编辑 → 编辑行就地替换当前行 → 控件收集 → api.updateBook(id, patch【含 status/category_id/rating/favorite/tags】)
   → 成功: 换回普通行 + toast + refresh()（静默）+ refreshSidebar()
   → 失败: toast，保留编辑态可重试；取消: 直接还原普通行
```

数据流（抓取刷新）：

```
点刷新（仅 douban_url/isbn 非空显示）→ 按钮局部 loading → api.fetchMetadata({url|isbn})
   → 成功: api.updateBook(id, mapped【cover_url 非空才带，douban_url 不覆盖】)→ toast
   → 失败: toast(err)，不动数据
   → 结束: 按钮恢复 → refresh()
```

## 边界与错误处理

- 编辑态中触发刷新/筛选/排序/翻页等列表重渲染：`editingId` 为组件内局部状态，列表重渲染后编辑态自动退出，不导致数据错乱（未保存的修改丢弃，可接受）。
- 抓取保存在途时用户离开列表：按钮为局部状态，重渲染后刷新按钮恢复常态，不重复请求。
- 评分输入非法 / 空：保存前校验拦截并 toast。
- 豆瓣抓取偶发失败：接口已带错误信息文案，直接透出。
- 行内编辑行横向空间：表格在窄屏仍可横向滚动，控件采用紧凑宽度。

## 不做的事（YAGNI）

- 不做多选勾选批量操作。
- 不在行内编辑书名/作者/长文本字段。
- 不改动画格视图。
- 不新增后端接口。

## 验证方式

1. `npm run typecheck`、`npm run build` 通过。
2. 本地 `wrangler dev` + 本地 D1 seed 数据，浏览器验证：
   - 点击编辑 → 行切换为编辑形态，控件预填当前值；
   - 修改状态/分类/评分/收藏/标签 → 保存 → 列表与侧栏计数更新；
   - 取消 → 原样还原，无请求；
   - 有豆瓣链接的书显示刷新按钮，点击后抓取并保存，列表更新；无链接的书不显示；
   - 抓取失败时 toast 报错且原数据不变；
   - 编辑态下点收藏/行点击不误触。
3. 部署：`wrangler deploy --config wrangler.prod.toml`。
4. 截图存 `META/DATALAB/`，日志按规范记入 `META/LOG/`。
